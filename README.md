# skill-skip-pr-generator

スキルスキップの Instagram ストーリーズPR台本を、**過去PR実績データ × 25章プロンプト** から Claude Code で生成するプロジェクト。

毎回ゼロから生成する従来運用とは違い、PR者ごとの過去 PR概要 / 台本 / 数値結果 / 振り返り を Few-shot として読み込ませて、口調・展開・勝ちパターンを再現します。

---

## 30秒でわかること

- **入力**：`03.PR台本成果物とPR振り返り/稼働中/<A_連番_PR者名>/<YYYY-MM_第N回_切り口>/1.PR概要.md`（この回の狙い・ターゲット・訴求軸）
- **参照**：同じPR者の過去PR全部（1.PR概要 / 2.台本 / 3.数値結果 / 4.振り返り）＋ PR者専用差分プロンプト
- **出力**：`<同じパス>/生成台本（not fixed）/v<N>.md`（9セクション構成の完成台本）

依頼書・PR実施版・数字・教訓を **1PR1フォルダ** に集約するので、過去の勝ち回を横ずらしして新台本を設計できます。

## クイックスタート

```sh
cd ~/Documents/GitHub/skill-skip-pr-generator
claude
```

Claude Code 内で：

```
/PR者分析 A_001_30代ちゃん/2026-05_第5回_GW明け      # 過去事例から類似Top3〜5を抽出
/台本生成 A_001_30代ちゃん/2026-05_第5回_GW明け     # 台本を生成して 生成台本（not fixed）/v<N>.md に保存
/台本採点                                            # 別エージェントが辛口採点（任意）
```

これだけ。

## 詳細フロー

### 新規PR者の追加

**手動でフォルダを作ってはいけません**。必ず `/PR者登録` を使うこと（採番台帳との不整合を防ぐため）。

```
/PR者登録 美桜 A
```

これで以下が自動実行されます：
- `02.PR者データベース/採番台帳.md` から次の連番を採番（例：002）
- 01/02/03 の3トップに `A_002_美桜/` を同時作成
- 各トップに雛形（プロフィール／改善ログ／差分プロンプト等）をコピー
- 採番台帳に履歴を追記

その後、`02.PR者データベース/稼働中/A_002_美桜/プロフィール.md` を埋める。

### 新規PRを起こす

そのPR者のフォルダに新規PRフォルダを作成：

```sh
mkdir -p "03.PR台本成果物とPR振り返り/稼働中/A_002_美桜/2026-07_第1回_<切り口>"
cp -r "03.PR台本成果物とPR振り返り/雛形/YYYY-MM_第N回_訴求切り口/." \
      "03.PR台本成果物とPR振り返り/稼働中/A_002_美桜/2026-07_第1回_<切り口>/"
```

訴求切り口は `01.台本作成プロンプト/訴求カテゴリマスター.md` から選ぶ（表記揺れ防止）。

`1.PR概要.md` にこの回固有の依頼内容を書く：PR実施日数・特典・大テーマ・小テーマ・訴求軸など。

### 過去データの取り込み（あれば）

過去のPR実施履歴がある場合、そのPR者の `03.../稼働中/<A_連番_PR者名>/` 配下に同じ形式でフォルダを作る。埋められる範囲で埋める。

**埋まる情報が多いほど精度が上がる**。特に `4.振り返り.md` の「PR者が手直しした差分」表が暗黙知の宝庫。

### 生成・採点・修正

```
/PR者分析 <A_連番_PR者名>/<YYYY-MM_第N回_切り口>
/台本生成 <A_連番_PR者名>/<YYYY-MM_第N回_切り口>
/台本採点
```

生成された台本は `03.PR台本成果物とPR振り返り/稼働中/<A_連番_PR者名>/<YYYY-MM_第N回_切り口>/生成台本（not fixed）/v<N>.md` に自動保存。

### FB（フィードバック）を蓄積する

生成台本を読んで気付いた修正点・違和感を `/フィードバック` で記録：

```
/フィードバック A_001_30代ちゃん/2026-05_第5回_GW明け
```

Claudeが各FBに **二重判定** をかけて、必要なら複数階層に多重保存します：

- **判定1（発生スコープ）**：PR回／PR者／全体 のどこで気づいた問題か
- **判定2（適用範囲）**：このルールは普遍的か（PR原理）／PR者特有か（口調・癖）

例：

| FBの性質 | 保存先 |
|---------|--------|
| 「30代ちゃんは『リアル』を使わない」 | PR者のみ（口調癖） |
| 「業界用語は読者の防御反応を起こす」 | PR者 + 全体（PR原理として普遍） |
| 「この回はえんめ登場枚を減らす」 | PR回のみ |

```
01.台本作成プロンプト/1.基本プロンプト/基本_汎用台本_改善ログ.md                              ← 全PR者共通の昇格候補
01.台本作成プロンプト/2.PR者別差分プロンプト/稼働中/<A_連番_PR者名>/改善ログ.md                ← このPR者特有のFB
03.PR台本成果物とPR振り返り/稼働中/<A_連番_PR者名>/<PR回>/フィードバック.md                     ← この回限定FB
```

**PR者特有のFBは全体に上げない**ので、他PR者の台本生成が30代ちゃんの口調癖に引きずられる事故が起きません。

### PR実施後（次回精度のための学習）

同じPRフォルダ内で：

- `2.台本.md` ← PR実施版を貼る
- `3.数値結果.md` ← 数字（予約・参加率・入会数など）
- `4.振り返り.md` ← 効いた／滑った／PR者が手直しした差分

複数PR者で再現したパターン（3エントリ以上の反復FB）は `/昇格` コマンドで `01.台本作成プロンプト/1.基本プロンプト/基本_汎用台本プロンプト.md` の該当章に転記される。

### PR者のランク変動・ステータス変動

**手動でフォルダ操作しないこと**。3トップで同期が崩れます。必ずコマンドを使う：

```
/PR者ランク変更 001 B                    # A_001_xxx → B_001_xxx に3トップ同時リネーム
/PR者ステータス変更 050 休眠中            # 稼働中/A_001_xxx → 休眠中/A_001_xxx に3トップ同時移動
```

休眠中／アーカイブ の親フォルダが存在しない場合は `/PR者ステータス変更` 実行時に自動作成されるので、事前準備は不要です。

## スラッシュコマンド

### 台本生成・改善フロー

| コマンド | 役割 | 引数 |
|---|---|---|
| `/PR者分析` | 過去PRから類似Top3〜5を選定。設計類似度（過去PR概要比較）も評価軸に含む | `<A_連番_PR者名>/<YYYY-MM_第N回_切り口>` |
| `/台本生成` | PR概要＋類似事例＋25章プロンプト＋PR者別差分＋FB3階層で台本生成。生成物を自動保存 | `<A_連番_PR者名>/<YYYY-MM_第N回_切り口>` |
| `/台本採点` | 別エージェントとして辛口採点・書き換え提案 | なし（直近生成物を対象） |
| `/フィードバック` | 生成台本へのFBを3階層（全体／PR者／PR回）に分類して追記蓄積 | `<A_連番_PR者名>/<YYYY-MM_第N回_切り口>`（省略可） |
| `/昇格` | 3階層に溜まった未昇格FBから、3件以上反復・普遍ルールを上位本体に転記。月1回など定期メンテで実行 | なし |

### PR者管理フロー（3トップ同期）

| コマンド | 役割 | 引数 |
|---|---|---|
| `/PR者登録` | 連番採番＋3トップに同IDフォルダ作成＋雛形コピー＋台帳追記 | `<名前> <ランク>` |
| `/PR者ランク変更` | 01/02/03の3トップで `<旧ランク>_<連番>_<名前>` → `<新ランク>_<連番>_<名前>` を一括リネーム | `<連番> <新ランク>` |
| `/PR者ステータス変更` | 01/02/03の3トップで PR者フォルダを 稼働中／休眠中／アーカイブ 間で一括移動 | `<連番> <新ステータス>` |

## 出力フォーマット（生成された台本の中身）

`/台本生成` の出力は常に9セクション：

| # | セクション | 内容 |
|---|---|---|
| 0 | PR概要情報 | 対象 `1.PR概要.md` を全文転記 |
| 1 | 設計サマリー | 主軸パターン・過去PR概要との差分・横ずらし箇所 |
| 2 | 全体構成サマリー | Day別の役割・枚数・CTA配置 |
| 3 | 過去/現在マッピング表 | PR者のBefore→After |
| 4 | 台本本体 | Day別・枚別の全文 |
| 5 | 各日のCTA設計 | タイミング・損失回避軸 |
| 6 | お祭り化パーツ集 | 数字告知・社会的証明 |
| 7 | キャンセル防止 | Phase14〜18 |
| 8 | 想定Q&A | 5問 |

第13・17〜24章の適合チェックは内部で必ず実行され、NG箇所は出力前に書き換えられます。詳細採点は `/台本採点` で。

## 設計思想

- **1.PR概要.md はPRごとに新規作成** — 毎回ターゲットと訴求が変わるので依頼書も毎回新規。**過去のPR概要は「横ずらし」素材**（勝ち回のPR概要を参考に新PR概要を設計）。
- **既存プロンプトは "型"、過去データは "魂"** — 25章プロンプトはあくまで構造設計。実データを Few-shot として注入して、抽象を具体に降ろす。
- **1PR1フォルダで完結** — 1.PR概要 / 2.台本 / 3.数値結果 / 4.振り返り / 生成ドラフトが同居。後から見返したとき「当時こういう設計でこの数字、PR者はこう手直しした」が一覧できる。
- **生成は1発で終わらせない** — `/台本生成 → /台本採点 → /フィードバック → 再生成` を最低1ループ回す。
- **FBは3階層で蓄積** — 全体／PR者／PR回の粒度を分けることで、過剰般化も過剰個別化も避ける。FBが溜まるほど次回精度が上がる。
- **学びを蓄積資産化** — PR実施後の `4.振り返り.md` と FB3階層を貯めるほど、`/昇格` で確定ルールが上位本体に溶け込み、累積的に精度が上がる構造。
- **PR者管理は3トップ同期** — ランク・ステータス変動は必ず専用コマンドで実行。手動操作は採番台帳との不整合を生む。
